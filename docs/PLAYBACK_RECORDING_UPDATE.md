# 0.6.0 回放与录像更新

日期：2026-11-05。本轮实现独立回放、录像来源分类、活动提醒隔离和录制范围命名；根据用户发布请求同步源码并提供 [v0.6.0 预发布入口](https://github.com/JinzhongYe/RTSPMonitor/releases/tag/v0.6.0)，仍使用调试签名。

## 行为

- 录像列表的“回放”打开独立 Activity。专用 ViewModel/播放器支持暂停、恢复、0.5/1/1.5/2 倍速、当前位置/总时长、拖动松手跳转及横竖屏。旋转保留播放器和倍速，退出释放回放资源，不操作摄像机或录像服务。
- 新录像按分段累计来源：手动、活动或手动＋活动。重叠共用录像任务，不重连、不额外切段；列表支持全部、手动、活动筛选，混合段同时属于两类。
- 文件名示例：`20261105_103000-20261105_103500_手动.mp4`。两端均为完整日期时间，冲突追加序号；应用内与相册导出保持同名。历史文件不批量改名，缺乏元数据时显示时间/来源未知。
- 起点以手机开始写入该段视频时的时间为锚点，终点根据写入的视频 PTS/时长计算，不使用停止按钮或相册导出的时间；不是摄像机提供的可信采集 UTC。保存录制时的时区偏移，之后更改手机时区不改变名称。
- 原生写入后发送时间信息；录像引擎将时间、时区、累计来源写入 AtomicFile 旁路元数据。普通写入约每秒持久化一次，来源变化和正常分段结束立即持久化。发布索引及异常恢复携带这些字段；裁剪损坏尾片后依据保留视频样本收缩结束时间。
- Room 升至版本 3，新增可空起止时间、时区偏移和来源掩码，保留 1→2→3 迁移；旧行来源为未知，保留原文件名与导出 URI。
- 自动监控开启时沿用现有人形/画面差异与去抖策略。新活动通知包含设备名称、活动原因和时间；持续同一事件不重复提醒。活动通知使用独立 ID，不再被录像准备、保存或失败通知覆盖。通知权限或活动渠道关闭时页面提示；不会因此关闭录制。

## 发现的环境阻塞

开启自动监控的完整通知测试实际执行时，MediaPipe tasks-vision 1.2.2 在 `drishti` 原生线程 SIGILL 崩溃。故障地址 `0xe3d854` 反汇编为 `rdsvl x0, #1`，与 Apple Silicon 主机上 ARM64 Android 模拟器执行 SME 指令的[上游问题](https://github.com/google-ai-edge/mediapipe/issues/6293)一致。这是原因推断，不能由模拟器结果确认物理手机受影响范围。未降级依赖、替换检测方案或将此失败计为通过；保留了失败输出和原生堆栈。

需要在支持该库的物理手机上执行显式通知测试：安装 app 与 app AndroidTest APK，准备可达的本地合成 RTSP `h264` 流，允许通知，然后：

```bash
adb shell am instrument -w \
  -e class com.rtspmonitor.app.PlaybackIsolationTest#activityNotificationSurvivesRecordingStatusAndMixedSourceIsSaved \
  -e runActivityNotifications true -e rtspBase rtsp://HOST:18554 \
  com.rtspmonitor.app.test/androidx.test.runner.AndroidJUnitRunner
```

该测试向检测器注入黑白合成帧，检查通知不被录像状态覆盖及自动/手动重叠分类；不能替代真实场景的人形识别、误报率或锁屏测试。

实际摄像机、本地通知中心展示/点击、拒绝权限/关闭渠道、30 分钟真机锁屏和高负载下回放隔离仍需设备验收。当前电脑访问不到用户摄像机，没有保存或使用其真实凭据作为测试夹具。
