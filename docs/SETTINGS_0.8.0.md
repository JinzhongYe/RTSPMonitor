# 0.8.0 检测阈值与手动分段设置

入口为监控页“检测与录像设置”，不与连接凭据混用。运行任务时也可修改。

| 参数 | 范围 | 默认 |
|---|---|---|
| 人形置信分 | 0.10～0.95，步长0.05 | 0.60 |
| 变化面积 | 1%～30%，步长1% | 3% |
| 像素亮度差 | 5～100，整数 | 25 |
| 手动录像每段时长 | 1～60分钟，整数 | 5分钟 |

数值越低越容易触发，也可能增加误报。保存后立即生效，取消不保存；恢复默认先还原表单，点击保存后持久化。非法时长禁用保存。缺失或损坏的偏好配置使用默认值；不迁移数据库或修改密码存储。

检测模型的输出置信门槛设为0.10，按当前配置过滤人形结果；亮度与面积使用当前不可变配置快照。旧配置下的异步结果丢弃，阈值变化清除未确认的连续计数，不直接结束已活动事件。采样500ms、连续两次确认及30秒无活动收尾策略不变。

手动时长指每个文件的分段长度，不是自动停止总时长。活动录像仍为300秒，混合录像手动优先。停止手动但活动仍持续时恢复300秒；若当前段已超过新上限，在下一关键帧收尾。延长上限继续当前段；已经写入的内容不回切，不重编码、不另开RTSP连接。

`RecordingEngine.setSegmentSeconds` 经同步句柄保护更新JNI原子值，原生读流循环动态读取上限。重连创建的新引擎采用会话当前有效设置；停止收尾时保留最后有效参数与来源，避免不必要的新分段。

## 本地实际检查

- Gradle构建、lint、28项JVM单元测试通过：阈值边界、默认值、非法配置、手动/活动时长选择和去抖证据清除。
- 设置持久化仪器测试1项通过：重新实例化读取、默认值、损坏配置回退；结束后恢复原配置。
- 原生录像5项通过，包括H.264/H.265、双路独立停止、来源累计，以及同一任务在分段开始事件后将上限8→2→4秒，输出约2秒和4秒片段并解码成功。这是加速验证，不是分钟级长测。
- 运行中设置/录像隔离1项通过：手动录像期间把配置改为1分钟，会话上限变为60秒并恢复原值，任务实例不变；回放、导出、删除依旧不停止录制。测试类另有1项活动原生测试显式跳过。
- 已查看正常及1.4倍字体的设置截图，滚动区域与保存/取消按钮可用。
