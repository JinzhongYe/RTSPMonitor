# 0.7.0 回放布局优化

依据工作区 `1032.JPG` 的播放器、日期和按小时分组的录像布局实施。照片没有复制到工程资源中；没有增加云录像、AI 识图、收藏等无对应能力的入口。本地验证完成后按用户请求同步源码，并提供 [v0.7.0 预发布入口](https://github.com/JinzhongYe/RTSPMonitor/releases/tag/v0.7.0)。发布包沿用项目固定测试签名。

## 布局与行为

- 监控页保留实时连接、手动录像及自动监控操作；录像区改为数量与“查看录像”入口。
- 回放页固定标题与 16:9 播放器，下方为日期选择、前后一天、全部/手动/活动筛选及按小时倒序的缩略图。默认选择最近有录像的一天，从指定录像进入时选择对应日期并播放。
- 普通手机显示三列；宽度小于 360dp 或字体倍率大于 1.2 时显示两列。未知时间的旧录像单独浏览，不根据创建时间猜测拍摄日期。
- 播放器支持暂停/恢复、前后 10 秒、倍速、进度拖动与横屏全屏；返回先退出全屏。日期和来源筛选只改变列表，不停止正在播放的片段。
- 当前片段以边框和标签标记，导出、删除放入“更多”菜单。删除当前片段先关闭本地文件输入，不调用录像服务停止接口。
- 缩略图采用系统 MediaMetadataRetriever 后台提取、两个并发许可、12 MiB 内存缓存及应用私有磁盘缓存。删除时清理缓存，并阻止未完成提取重新写回已删除的条目。提取失败显示占位，不阻塞主线程。
- 没有数据库迁移，没有修改录制引擎、文件命名或检测模型。

## 验证结果

[机器摘要](evidence/ui-0.7.0/summary.json)记录最终 APK SHA-256。截图均为合成测试录像，不是真实摄像机图像。

| 检查 | 实际结果 |
|---|---|
| assembleDebug、testDebugUnitTest、lintDebug | PASS，核心 22 项及新增浏览规则 2 项，共 24 项单元测试通过 |
| 普通竖屏约 393dp | PASS，三列；已查看截图 |
| 窄屏 320dp | PASS，两列；按钮和日期可见，已查看截图 |
| 字体倍率 1.4 | PASS，两列；已查看截图 |
| 横屏全屏 | 实际点击验证 PASS，仪器用例确认设备方向为横屏并保存截图；无障碍节点检索在此环境未定位到 Compose 按钮，未将其记作成功的自动点击 |
| 录像期间回放、倍速、旋转、导出、删除 | PASS，录像任务保持原实例且持续运行，停止后文件有效 |
| 回放 Activity 重建 | PASS，播放器/URI/倍速保留，PixelCopy 检查实际出帧 |

回放隔离测试类中的活动通知用例显式跳过，`OK (2 tests)` 实际为一项通过、一项跳过；现有 ARM64 模拟器 MediaPipe 原生崩溃限制仍见上一轮报告。
